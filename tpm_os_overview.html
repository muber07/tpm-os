Why TPM OS

Running a program means synthesizing dozens of signals every day. TPM OS automates the gathering so you can focus on the decisions.

📡

Ground-truth gathering

Pulls Jira, Slack DMs, and docs automatically. Every field traces back to a specific source with a timestamp.

🧠

Confidence scoring

HIGH (2+ sources), MEDIUM (1 source), LOW (inferred). Know how certain the system is before you act.

😈

Devil's Advocate built in

Every proposed update is adversarially challenged across 6 categories. Challenges must cite a ticket ID or Slack timestamp.

✅

You stay in control

The pipeline never auto-advances past the human approval gate. Full context — one screen.

🔍

Verified state

The Verifier cross-checks against live Jira and Slack. Each field is stamped with a verified_at date.

📄

Instant outputs

Newsletter, exec brief, risk tracker, escalation memo — generated from verified state. Every claim is sourced.

📂

Multi-program by design

One config per program under programs/[name]/. Skills are program-agnostic.

🔓

Any org, any program

No vendor lock-in. Configure your data sources in YAML and the full pipeline works for any program.

Get Started

TPM OS is multi-program by design. One config file per program. Skills are program-agnostic.

1
Setup

Create a program directory

Each program lives in its own folder under programs/. Copy the template to get started.

mkdir -p programs/my-program
cp templates/config.yaml programs/my-program/config.yaml
cp templates/PROGRAM_STATE.yaml programs/my-program/PROGRAM_STATE.yaml
2
Configure

Configure your data sources

Edit config.yaml with your Jira project, Slack channels, and stakeholder list.

program_name: "My Program"
jira_project: MYPROJ
jira_initiative: MYPROJ-001
slack_channels:
  - "#my-program-eng"
  - "#my-program-pm"
slack_dms:
  - alice@company.com
  - bob@company.com
stakeholders:
  - name: Alice (PM)
  - name: Bob (Eng Lead)
3
Run

Run the pipeline

Tell Claude Code to run TPM OS. The pipeline gathers signals, proposes a delta, runs the Devil's Advocate, then stops for your approval.

# Full pipeline run
run tpm-os program=my-program

# Individual stages
run tpm-os stage=signal-fetch program=my-program
run tpm-os stage=synthesize program=my-program
4
Approve

Review and approve

You see the proposed delta, DA challenges, contradictions, and confidence scores. Reply to commit or correct.

# Approve the proposed state
approved

# Or correct and loop back
The M3 launch date should be Sep 30, not Oct 15.
Loop back to Synthesizer with this correction.

Common Commands

Full pipeline run

run tpm-os program=<name>

Fetch → Synthesize → Detect → DA → Pause → Verify → Render → Publish

Generate newsletter

generate newsletter program=<name>

Reads verified PROGRAM_STATE and generates the weekly stakeholder newsletter.

Verification pass

run verify program=<name>

Pulls live Jira and Slack. Flags every field not verified in 7 days as STALE.

Exec brief

generate exec-brief program=<name>

One-page executive summary: status, risks, decisions needed, key dates.

Escalation memo

generate escalation program=<name>

Structured escalation memo with context, ask, and path to green.

Risk tracker

generate risk-tracker program=<name>

Risk table with owner, likelihood, impact, and mitigation path.

Devil's Advocate

Stage 3 · Evidence-required challenge layer

Adversarially challenges every proposed state delta. Every challenge must cite a specific ticket ID, Slack timestamp, or date gap — vague concerns are automatically rejected.

6 Challenge Categories

🕐 Staleness
⚡ Contradictions
👤 Ownership gaps
📋 Unverified commitments
📈 Optimism bias
🔕 Missing signal
Outcome: APPROVED or REJECTED.
REJECTED → Synthesizer re-runs with da_challenges.md. Loops until DA approves or you override.
🔍

Verifier

Stage 4 · Live cross-check after approval

After your approval, pulls live state from Jira and Slack to confirm every committed field matches. Flags discrepancies and routes back to SignalFetcher with specific fields to re-check.

What it stamps on every field

milestone_m3_launch:
  value: "2026-09-30"
  confidence: HIGH
  sources:
    - MYPROJ-142 (updated 2026-06-08)
    - PM Slack DM 2026-06-09 10:42am
  verified_at: 2026-06-11T09:15:00Z
Fields not verified in 7 days are automatically flagged as STALE in the next pipeline run.
